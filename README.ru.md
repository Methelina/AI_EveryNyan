# 🐱 AI_EveryNyan v0.18.0 — Smart Desktop Assistant with Hybrid Memory & MCP Tools

> *"Haru, everynyan! How are you!? Fine, thank you! I wish I were a bird!"*

**AI_EveryNyan** — это десктопное AI-приложение с продвинутой архитектурой памяти и поддержкой внешних инструментов через MCP (Model Context Protocol). В отличие от обычных чат-ботов, EveryNyan ведет "цифровой дневник", суммирует разговоры, может искать информацию в интернете (через SearXNG) и извлекать содержимое веб-страниц.

Приложение построено на Python, использует локальные модели (Ollama или LLaMA-сервер) и гибридную систему хранения: **DuckDB** для точной истории и **Qdrant** для семантических ассоциаций.  
**Текущая версия:** v0.18.0 — с системой персон (персоно-изолированные хранилища памяти), переработанным табовым GUI (VHS-шрифты, аватары-«буквицы»), мультибэкенд-поддержкой (Ollama / LLaMA / OpenAI-совместимые), стримингом ответов, MCP-агентом и самовосстанавливающимися бэкендами (Qdrant, SearXNG, ComfyUI).

## ✨ Ключевые особенности

### 🧠 Гибридная архитектура памяти (DuckDB + Qdrant)
Система разделяет хранение на два уровня:
*   **DuckDB (SQL):** Структурированная хронология чата, дневниковые записи и точные метаданные.
*   **Qdrant (Vector DB):** Эмбеддинги диалогов и размышлений. Обеспечивает RAG (Retrieval-Augmented Generation) — поиск информации по смыслу.

### 👤 Система персон и персоно-изолированная память
У каждой персоны — собственное изолированное хранилище, выбор происходит в лаунчере **до** старта Python:
*   **DuckDB:** `data/memory/<Персона>/history.db` — история чата и дневниковые записи.
*   **Коллекция Qdrant:** `everynyan_diary__<Персона>` (персона по умолчанию **EveryNyan** сохраняет легаси-имя `everynyan_diary`).
*   **Файлы дневника:** `data/memory/<Персона>/diary/`.
Персона передаётся в рантайм через переменную окружения `AI_EVERYNYAN_PERSONA` и разрешается до любой инициализации — никакого «горячего» переподключения открытых БД. Смена персоны = перезапуск лаунчера с выбором другого пункта; внутри сессии GUI переключает только наборы внешности (скины), память они не затрагивают.
Разовый миграционный скрипт (`scripts/migrate_memory_to_persona.py`, идемпотентный, с бэкапом в `temp/backup/`) переносит легаси-общий `data/history.db` в `data/memory/EveryNyan/`.
Личность персоны живёт в `config/character/base.yaml` (`meta.persona_name`); набор внешности может опционально переопределить промпт персоны файлом `base_<Набор>.yaml` — пока `persona_name` не меняется, влияние на память нолевое.

### 🖥️ Переработанный табовый GUI
Окно разделено на три вкладки — **CHAT** (чат + ввод), **CONSOLE** (`[SYSTEM] LOG`), **SETTINGS** — в тёмной палитре CrisTical (янтарные акценты), с VHS-шрифтами (ModeSeven в заголовках, ModeSeven в подписях, VCR OSD Mono RUS в чате), заглавными заголовками секций и **аватарами-«буквицами»**: если есть `config/character/ava_<Набор>.png`, изображение встаёт рядом с сообщением как буквица — первые четыре строки текста идут рядом с ним, остальное продолжается на полную ширину ниже.

### ⏳ Sliding Window & Smart Dump
Уникальный алгоритм управления контекстом:
1.  Когда буфер переполняется, ИИ пишет запись в дневник, выделяя суть, эмоции и сущности.
2.  Текст разбивается на смысловые блоки, проверяется на плагиат (через Qdrant) и сохраняется.
3.  Оперативная память очищается, диалог продолжается с чистого листа, но знание сохранено навсегда.

### 📋 Структурированные метаданные дневника (JSON + циркумплексная модель)
Каждая запись дневника содержит извлечённые LLM метаданные:
- Сущности (`entities`), теги (`topics`), поисковые фразы (`retrieval_cues`).
- **Аффект:** валентность (−1…+1) и возбуждение (−1…+1) по модели Рассела, плюс текстовая метка эмоции.
- Важность, отношения, противоречия и ключевые факты.

### 🛡️ Graceful Shutdown
Приложение перехватывает сигналы закрытия. Перед выходом оно принудительно вызывает `dump_context_to_memory`, чтобы ни одна мысль не потерялась.

### 🚫 Анти-повтор (Semantic Anti-Repeat)
Косинусное сходство новых сообщений с историей. Если ИИ начинает повторяться (average similarity > 0.73 или max > 0.69), детектируется петля и тема меняется.

### 👁️ AI Internal Thoughts UI
Панель "Внутренних мыслей" в DearPyGui показывает процессы в реальном времени: RAG-запросы, вызовы инструментов, ошибки, reasoning_content моделей. В v0.16.2 добавлено **цветное логирование MCP инструментов**: вызовы (жёлтый) и результаты (зелёный/красный).

### 🔌 Три бэкенда: Ollama, LLaMA и OpenAI-совместимые
- **Ollama** — основной режим, полная поддержка стриминга и метаданных.
- **LLaMA** — режим для локальных серверов (например, `llama-server`). В v0.16.1 полностью исправлен критический баг сохранения ответов, в v0.16.2 добавлен fallback на прямой LLM при ошибках агента.
- **OpenAI-совместимый** (`openai_compat`) — любой сервер с `/chat/completions` + `/models`: OpenAI, OpenRouter, Mistral, LM Studio, vLLM. Настраивается тремя полями: `base_url`, `api_key`, `chat_model`. Переключается на лету из GUI.

### 🧹 Лемматизация для RAG (через spaCy)
Текст сообщений и дневников перед индексацией обрабатывается через `ru_core_news_sm` и `en_core_web_sm`, что повышает качество поиска.

### 🔧 MCP-инструменты (Model Context Protocol)
Все инструменты автоматически обнаруживаются из `tools/mcp/tool_*.py` и подключаются через stdio-транспорт. Каждый инструмент — независимый FastMCP-сервер.

#### 🌐 Веб-поиск и навигация (SearXNG)
- **`web_search`** — анонимный метапоиск через SearXNG (без API-ключей). Результат в Markdown.
- **`fetch_url`** — извлечение содержимого веб-страниц с поддержкой трёх режимов: `legacy` (httpx+bs4), `playwright` (полный браузер), `nodriver` (лёгкий CDP). Автоматическое очищение HTML → Markdown.
- **`open_url`** — открытие ссылки в системном браузере пользователя.

#### 🧮 Математика и конвертация
- **`calculate`** — безопасный калькулятор математических выражений (арифметика, тригонометрия, логарифмы, `pi`, `e`).
- **`convert_units`** — конвертация единиц: температура (C/F/K), длина, вес, объём данных, время.

#### 💱 Курсы валют
- **`convert_currency`** — конвертация суммы между валютами по актуальным курсам (без API-ключей, ~150+ валют).
- **`exchange_rate`** — текущий курс для пары или группы валют.
- **`list_currencies`** — список всех поддерживаемых валют.

#### 🕐 Дата и время
- **`get_datetime`** — текущая дата/время с поддержкой таймзон и произвольного форматирования.
- **`get_timestamp`** — Unix timestamp и ISO 8601.
- **`format_datetime`** — форматирование timestamp в читаемый вид.
- **`time_diff`** — человекочитаемая разница между двумя датами.

#### 🌤️ Погода
- **`get_weather`** — текущая погода для города/координат (через wttr.in, без API-ключей).
- **`get_forecast`** — прогноз на 3 дня.

#### 🎲 Генерация случайных значений
- **`generate_uuid`** — UUID v4 (random) или v7 (time-ordered).
- **`generate_random_string`** — пароли, токены, произвольные строки с выбором charset.
- **`generate_random_number`** — случайные числа (int/float) в диапазоне.
- **`pick_random`** — случайный выбор из списка.

#### 📁 Песочница файловой системы (Workspace)
Только чтение, все пути валидируются против `workspace_dir` (путь traversal и symlink-эскейпы блокируются).
- **`read_file`** — чтение файла (текст/бинарный, с offset/limit).
- **`check_path`** — проверка существования и типа пути.
- **`list_directory`** — содержимое директории с сортировкой и фильтрацией.
- **`search_files`** — поиск файлов по glob-паттерну.
- **`directory_tree`** — дерево директорий.
- **`file_info`** — метаданные файла (размер, даты, строки, SHA-256).
- **`grep_content`** — поиск по содержимому файлов (regex).

#### 🖥️ Системная информация
- **`get_system_info`** — ОС, hostname, uptime, CPU, RAM, диск (с фильтрацией секций).

#### 👁️ Vision (анализ изображений)
- **`describe_image`** — анализ изображения через VL-модель. Авто-определение vision-способности активного чат-модели (Ollama / llama.cpp). Два режима: `structured_json` (детальный JSON: человек/сцена) и `free_text`. Поддержка локальных файлов и URL.

#### 🎨 Генерация изображений (ComfyUI)
- **`generate_image`** — генерация через ComfyUI: отправка workflow, ожидание через HTTP polling, сохранение результатов на диск.
- **`list_workflows`** — список доступных workflow JSON из `workflows/`.

#### 🧑‍🎨 Управление персонажем
- **`update_character_appearance`** — изменение внешности активного персонажа через LLM: волосы, одежда, макияж, аксессуары и т.д. Система проекций (`reprojection/`) с Pydantic-валидацией и locked-полями.

#### 🔧 Инфраструктура
- **Цветное логирование** всех вызовов инструментов и результатов в панели SYSTEM LOG.
- **Fallback при ошибках агента** — если MCP-агент упал, система переключается на прямой вызов LLM.
- **Автообнаружение** — все `tool_*.py` подключаются автоматически через `__init__.py`.
- **Цепочка фолбэков SearXNG** (`mcp_health`) — локальный инстанс по plain HTTP; если он мёртв, публичные инстансы пробуются ТОЛЬКО через nodriver (plain HTTP там получает 429/403), с кэшем здоровья и кулдаунами; если мертвы все — `web_search` исключается из агента (fail soft, log loud).
- **Обработка мёртвой модели** — 410/retired/429 получают дружелюбные сообщения; рейтлимиты отрабатываются Kilo-стилем тихой лестницей (10/30/60 с) без спама в чат; после исчерпания — fail-fast кулдаун против циклов, смена настроек чата его сбрасывает. Синтетические ошибки НИКОГДА не сохраняются в память.
- **Защита от стейл-агента** — после смены модели react-агент пересобирается инлайн до генерации, старый бэкенд не может ответить.
- **Временная осознанность** — в системном промпте текущее локальное время, в истории сообщения с префиксами `[ГГГГ-ММ-ДД ЧЧ:ММ]` — персонаж понимает, когда что произошло. Эхо-префиксы вычищаются из ответов.
- **Копирование чата** — двойной клик по сообщению копирует его текст в буфер.

### 🖥️ ComfyUI: автообнаружение
`comfyui.server` из `settings.yaml` — единственный источник истины. Если настроенный эндпоинт не отвечает, рантайм сам находит запущенный ComfyUI сканированием python-процессов (эвристика по cmdline + `--port` + HTTP-верификация) — смена порта в лаунчере ComfyUI никогда не рассинхронизирует монитор и `generate_image`.

### 🔄 Автообновление Chromium (`browser_updater`)
Ревизии браузера привязаны к версии пакета playwright. При старте рантайма (и в инсталляторе) апдейтер проверяет PyPI, обновляет playwright, докачивает Chromium, гоняет настоящий смоук-тест и только потом удаляет старые ревизии. Гейты: `browser_update.enabled` + `check_interval_days`; прогресс скачивания виден в консоли.

### 🗄️ Qdrant: Docker-first + портативный фолбэк
Векторная БД может работать в двух режимах с полной совместимостью данных:
- **Docker-контейнер** (`qdrant/qdrant`) — основной режим, управляется `run_qdrant.ps1`.
- **Портативный бинарник** (`bin\qd\qdrant.exe`, v1.19.1) — автоматический фолбэк при недоступности Docker, также поднимается самим рантаймом (`src/qdrant_backend.py`), если Qdrant не запущен.

Оба бэкенда обслуживают один и тот же `http://localhost:6333` и одно хранилище `data\qdrant_storage` (форматы сегментов и WAL побайтово совместимы) — коллекция переживает переключение Docker ↔ exe в обе стороны, а Python-код бэкенд не различает вовсе. Принудительный выбор бэкенда — `$use_portable_qd = 1` в `run_qdrant.ps1`.

## 🚀 Быстрый старт (Автоматическая установка)

Приложение включает автоматический инсталлятор на PowerShell.

### Требования
- **PowerShell**
- **Conda** (Miniforge или Anaconda)
- **Docker Desktop** (опционально — для Qdrant в контейнере; без него Qdrant работает через портативный бинарник `bin\qd`)
- **Ollama** или любой LLaMA-сервер с OpenAI‑совместимым API

### 1. Установка
```powershell
.\install_ai_everynyan.ps1
```

**Что делает скрипт:**
- Проверяет Git, Conda, Ollama (Docker — опционально, при отсутствии предупреждает).
- Создаёт структуру папок и Conda-окружение `env` с Python 3.12.
- Устанавливает зависимости из `requirements.txt`.
- Скачивает модель эмбеддингов **`bge-m3`** через Ollama.
- Скачивает и распаковывает **портативный Qdrant** в `bin\qd\` (обязательный шаг [2b/8] — гарантированный фолбэк-бэкенд).
- Генерирует `config/settings.yaml` (dim=1024).

### 2. Настройка (Опционально)
Отредактируйте `config/settings.yaml`. Пример:
```yaml
chat_mode: "ollama"   # или "llama"
ollama:
  chat_model: "qwen2.5:7b"
llama:
  base_url: "http://127.0.0.1:8088/v1"
  chat_model: "Falcon-H1R-7B-Q8_0.gguf"
# Для MCP инструментов (SearXNG)
searxng_url: "http://localhost:2597"
```

> **Важно:** `embedding_model` должен быть `bge-m3:latest`, `embedding_dim` — `1024`.

### 3. Запуск
1. **Qdrant:** `.\run_qdrant.bat` — Docker-first; если Docker недоступен (или `$use_portable_qd = 1` в `run_qdrant.ps1`), автоматически скачивается и запускается портативный бинарник из `bin\qd\`. Рантайм также сам поднимает портативный бэкенд, если Qdrant не запущен. Питон-часть не замечает разницы (тот же `http://localhost:6333`, то же хранилище `data\qdrant_storage`).
2. **SearXNG (для веб-поиска):** `.\run_searxng.bat` — если контейнер не поднят, рантайм переключается на проверенные публичные инстансы (проба через headless-браузер); если мертвы и они — `web_search` исключается из MCP-агента с предупреждением (fetch_url работает без него).
3. **Ollama / LLaMA-сервер / OpenAI-совместимый эндпоинт** — лаунчер дополнительно пингует выбранную `chat_model` и предупредит, если она мертва или рейтлимитится, ещё до старта приложения.
4. **Приложение:** `.\run_ai_everynyan.bat` — после баннера и префлайт-проверок лаунчер показывает **меню выбора персоны** (Enter = персона по умолчанию) ещё до старта Python, затем пингует выбранную `chat_model` и убивает зомби-инстансы прошлых запусков.

## 🧩 Как это работает

### 1. Асинхронная архитектура
GUI (DearPyGui) в главном потоке, LLM-запросы и RAG — в фоновом `asyncio` loop.

### 2. Пайплайн сообщения (v0.18.0)
1. **Anti-Repeat** — проверка на семантические петли.
2. **RAG** — поиск в Qdrant (с порогом схожести).
3. **Keyword search fallback** — если векторов нет, ищем в DuckDB.
4. **MCP Agent** — агент LangGraph с инструментами. Вызовы и результаты логируются цветом в панели мыслей.
5. **Fallback** — при ошибке агента → прямой LLM (Ollama или LLaMA).
6. **Стриминг** (LLaMA) — ответ появляется по токенам.
7. **Сохранение** диалога в DuckDB и Qdrant с извлечением метаданных.
8. **Smart Dump** — при переполнении контекста пишется дневник с JSON-метаданными.

### 3. MCP инструменты (12 серверов, 30+ инструментов)
| Сервер | Инструменты | Описание |
